# Table Reconciler H1 —— Excel / CSV 两表匹配与对账差异检测

把左右两张表按**你显式指定的**匹配键对齐，输出一份对账结果工作簿 + 一份文本报告：

```
左表（客户对账单）          右表（内部台账）
  订单号 = 单号   ←  匹配键，必须显式指定（单列，一对一）
  应收金额 = 金额 ←  比较字段，必须显式指定
        ↓
output/reconciliation.xlsx
    summary      六项统计 + 本次运行参数回显
    matched      键两边都有，且所有比较字段都一致
    differences  键两边都有，但有字段值不同（明确给出左值和右值）
    only_left    只有左表有的记录
    only_right   只有右表有的记录
output/report.txt            运行参数、文件指纹、统计、公式策略、警告
```

**它不做合并、不做清洗、不猜字段。** 它只做一件事：按你给的键把两张表对齐，然后如实告诉你哪里对不上。

## 环境

Ubuntu 24.04 自带的 Python 3.12 就够。处理 `.xlsx` 需要 openpyxl：

【Ubuntu】
```bash
sudo apt install python3-openpyxl
```

【Ubuntu】

## 默认口径：严格（这一条最重要）

**除了"去除首尾空白"，什么都不做。** 具体地：

| 情况 | 行为 |
|---|---|
| `"  A-1001  "` vs `"A-1001"` | **算相同**（去首尾空白是唯一允许的规范化） |
| `00123`（文本） vs `123`（数值） | **算不同** —— 键按文本处理，绝不吞掉前导零 |
| `ABC` vs `abc` | **算不同**（不忽略大小写） |
| `ＡＢＣ` vs `ABC` | **算不同**（不做全半角转换） |
| `"1,200"` vs `"1200"` | **算不同**（不处理千分位） |
| `1200` vs `1200.0000000001` | **算不同**（不做数值容差） |
| `"2026/1/1"` vs `"2026-01-01"` | **算不同**（不做日期智能识别） |
| 数值单元格 `1200.0` | 渲染成 `"1200"`（同一个数写成同一种形式，不是容差） |

设计取舍很明确：**宁可把业务上本来相同的数据列进 differences，也绝不因为过度标准化产生"假匹配"。**
假匹配会让你以为账平了，那是灾难性的；假差异只是多几个人工复核。

所有放宽口径的规则（忽略大小写、全半角、千分位、数值容差、日期识别、相似匹配）都留到 **H2**，
将来即使加上也必须显式开启，不会默认打开。

## 参数

| 参数 | 作用 |
|---|---|
| `--left` / `--right` | 左右两个文件（`.csv` / `.txt` / `.xlsx`），必填 |
| `--left-key` / `--right-key` | 匹配键列名（**单列**，必填；不支持复合键） |
| `--compare` | 比较字段，必填至少一个。写法 `金额` 或 `应收金额=金额`；逗号分隔或重复给多次 |
| `--left-sheet` / `--right-sheet` | `.xlsx` 的工作表名；**默认第一个工作表**，不猜 |
| `--left-header-row` / `--right-header-row` | 表头在第几行；**默认第 1 行** |
| `--left-delimiter` / `--right-delimiter` | CSV 分隔符；默认逗号 |
| `--output` | 结果工作簿路径，默认 `output/reconciliation.xlsx` |
| `--report` | 文本报告路径，默认 `output/report.txt` |
| `--work` | 中间目录，默认项目里的 `work/` |
| `--force` | 输出已存在时允许重跑；旧结果先归档到 `work/previous/`（保留，不删除） |

退出码：`0` = 顺利跑完（**有差异也是 0**，差异是正常结果不是失败）；`1` = 任何拒绝/失败。

## 四条安全保证

### 1. 原始文件绝对只读

`--left` / `--right` 指向的两个文件从头到尾只被读取。另外还有一道硬闸门：
**要写入的路径（`--output` / `--report` / `work/staging`）都不允许指向这两个原始文件**，
按 `resolve()` 后的真实路径判断，**符号链接也绕不过去**，而且**与 `--force` 无关** ——
`--force` 只放宽"覆盖自己以前的输出"，永不放宽"覆盖原始数据"。

被拒绝时磁盘上不会多出任何东西，**连输出目录的父目录都不会被创建**。

### 2. 绝不产生"看起来成功"的结果

- 结果工作簿和报告都**先在 `work/staging/` 完整生成**，全部校验通过后才一起提交到 `output/`。
- 提交顺序：先 `report.txt`，最后 `reconciliation.xlsx`；任何一步失败就**回滚**，
  删掉本次已提交的文件，`output/` 不留半套结果。
- 于是：**`output/` 里有 `reconciliation.xlsx`，严格等价于"本次运行成功"。**

### 3. 提交前做守恒校验（防静默丢行）

四类不变量，任一不过就禁止提交：

```
完全匹配 + 有差异 + 仅左表 == 左表数据行数
完全匹配 + 有差异 + 仅右表 == 右表数据行数
四张表的键集合两两不相交
summary 里的数字 == 重读结果文件实测出来的行数
```

### 4. 失败就整批停，不做局部成功

匹配键重复、空键、缺列、含公式、打不开、任一侧 0 数据行……全部**硬失败**，
不产出任何输出。理由：对账结果是要拿去跟客户/财务核对的，
一份"少了一部分数据但看起来成功"的结果比直接报错危险得多。

## 什么情况下会被拒绝

| 情况 | 处理 |
|---|---|
| 任一侧的匹配键**重复** | 硬失败，列出重复的键和行号（一对一的前提） |
| 任一侧的匹配键**为空** | **无条件硬失败**，退出码非 0，不产出任何文件。报错会指出是左表还是右表、空了几行、对应哪些原始行号。**没有任何参数可以绕过**（H1 没有 `excluded` 表，也没有"排除后继续"的口子） |
| 匹配键/比较字段**找不到** | 硬失败，并把该文件真实的表头打出来（带引号，能看出多余空格） |
| 某一列名在表头里出现两次（且被引用） | 硬失败（无法确定用哪一列） |
| 参与列（键列/比较字段列）里有**公式** | 硬失败，列出坐标 |
| 任一侧在表头行下面**一行数据都没有** | 硬失败（几乎总是选错了文件/工作表/表头行） |
| 左右指向**同一个文件** | 硬失败（自己跟自己比只会得到"全部匹配"的假结果） |
| `.xls` / `.xlsm` / `.xlsb` | 硬失败（请在 Excel 里另存为 `.xlsx`） |
| `--output` / `--report` 指向原始文件（含符号链接绕道） | 硬失败，与 `--force` 无关 |
| 输出已存在 | 默认硬失败；`--force` 才重跑，旧结果归档到 `work/previous/` |

## Excel 公式策略（明确设计，不无声使用过期缓存）

| 情形 | 处理 |
|---|---|
| 读 Excel | 一律 `data_only=False` —— 只拿得到公式串，**结构上不可能误用公式缓存值** |
| 参与列有公式 | **硬失败**。那时我们手里的"值"其实是 `=A1&B1` 这种公式文本，拿它当键或比较值必然是错的；改用缓存值又可能拿到过期结果 —— 两条路都不能走 |
| 非参与列有公式 | 不读、不影响结果，但报告里明确写出"忽略了 N 处" |
| `=` 开头的**文本**单元格 | 当文本正常接受（报告里给出警告），**输出时也强制写成文本，绝不写成公式** |

> 与姊妹项目（excel-cleaner / table-merger）的差别：它们在**重写**工作簿时分不清公式和文本，
> 所以整文件拒绝；本工具只读输入、另建工作簿输出，不存在把文本误写成公式的风险。
> 这是有意收窄，不是遗漏。

## 已知行为与边界（真实对账会遇到的）

- **尾部"合计"行**：键通常是空的 → **整批硬失败**，并指出是第几行。
  处理办法只有一个：**在源文件里删掉合计行**（或者让上游系统导出明细行）。
  这是刻意的 —— 如果工具替你"跳过合计行再继续"，你就会拿到一份**不完整却看起来成功**的对账结果，
  那正是 H1 最不能接受的东西。
- **金额一侧是文本、另一侧是数值**：比如左边 `"1200.00"`、右边数值 `1200`，严格比较下**会报差异**，
  而且报告里会专门提醒"两边类型不一致"。处理办法是把两侧导出成同一种格式（推荐都导出为文本）。
- **数值 vs 数字文本的键**：左边 `123`（数值）、右边 `"00123"`（文本）永远对不上。
  报告会在"两侧都有对不上的键"时提醒你检查导出口径。
- **超大数字**：Excel 的数字只能可靠保存 15 位有效数字，18 位订单号在 Excel 里就已经丢精度了，
  工具只能检测并告警，无法恢复。
- **隐藏行**：仍然参与对账（**不跳过** —— 跳过就是静默丢数据），但报告里会告警。
- **筛选状态**：读到的是全部行，不是筛选后可见的行，报告里会说明。
- **上下堆了两块数据的表**：第二块的表头会变成一条普通记录。工具不猜表结构，
  但如果发现"某一行的键和表头名一模一样"，会在报告里提醒你。
- **整行空白行**：不算记录，被忽略并在报告里计数。
- **表头不在第一行 / 多工作表**：用 `--left-header-row` / `--right-header-row` / `--left-sheet` / `--right-sheet`
  显式指定；默认严格取第 1 行 / 第一张表。
- **行号列**：是**源文件里的物理行号**（Excel 里看到的那一行），方便直接跳回去核对。
